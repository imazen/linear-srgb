# PR #30 against the frozen main baseline

Compared numerical source main
[`c5b83e3e`](https://github.com/imazen/linear-srgb/commit/c5b83e3e950e7e5955eb64174eddecc7a90d4c08)
against PR head
[`f168120c`](https://github.com/imazen/linear-srgb/commit/f168120c29a5e3f8e9f71ba0cd17e68ca1d3d4d5).
Both use the same committed golden runner, Rust 1.99.1 and dependency lock.
No expected hash was changed to compare the PR.

| Executed configuration | Result against main |
| --- | --- |
| Linux x86-64, V3 available | 4 changed chunks |
| Linux ARM64, NEON | Match |
| Strict WASM default | Match |
| Strict WASM precise-portable | Match |
| Linux x86-64, explicit V4 | 8 changed chunks, including the 4 V3 changes |

The V3 changes are `tokens::x8::{srgb_to_linear_v3,linear_to_srgb_v3}`.
The additional V4 changes are
`tokens::x16::{srgb_to_linear_v4,linear_to_srgb_v4}`. Each function changes
chunks covering output indices `61440..65536` and `65536..65792`. The first
chunk ends with the unit-grid white input; the second contains the edge
inputs. Other captured chunks, including ordinary dispatched APIs, match.

The small `endpoints` probe confirms the x8 white behavior:

| Input | Main x8 decode bits | Main x8 encode bits | PR x8 decode/encode bits |
| --- | --- | --- | --- |
| `1.0` (`3f800000`) | `3f7ffffa` | `3f7ffff9` | `3f800000` / `3f800000` |
| `1.0001` (`3f800347`) | `3f7ffffa` | `3f7ffff9` | `3f800000` / `3f800000` |
| `4.0` (`40800000`) | `3f7ffffa` | `3f7ffff9` | `3f800000` / `3f800000` |
| `+infinity` (`7f800000`) | `3f7ffffa` | `3f7ffff9` | `3f800000` / `3f800000` |

Main's x4 returns exactly 1.0 for these inputs. The PR's existing
[`ce451a6b`](https://github.com/imazen/linear-srgb/commit/ce451a6ba4d0)
white-endpoint fix aligns the wider hooks. Zero and the sampled input one ULP
below 1.0 match between main and the PR in the small probe. This probe does
not enumerate every differing input inside a changed chunk.

The main fixtures deliberately retain main's old bits. These differences must
remain visible during merge review; the frozen test is not currently a passing
test on the PR. Do not replace the fixture files with a PR-generated capture
without reviewing and authorizing the numerical delta.

To run the small probe on either source with this runner present:

```sh
CARGO_TARGET_DIR=target/goldens cargo run --locked --release \
  --manifest-path goldens/Cargo.toml --example endpoints
```

The regular golden checks are documented in [README.md](README.md). ARM64 and
V4 comparisons executed prebuilt test binaries on matching hardware, rather
than treating cross-compilation as execution evidence.
