# u8 encode alternatives, 2026-11-05

Source base: `1340e8645c7d5a2bc8d1922e9bbcfac319bd6166` plus the experiment sources committed with this record. Rust 1.99.1 on x86-64; 1.96.0 on aarch64. No target-cpu=native. Not measured on Zen 5.

Commands: `cargo run --release --example u8_encode_accuracy -- --exhaustive`, `cargo bench --bench u8_encode_options`, and `bash scripts/measure-encode-size.sh OUTPUT`, each through run-heavy (16G/10 jobs x86; 8G/4 jobs ARM). zenbench 0.1.11 interleaves candidates, using preallocated buffers. Exploratory measurements: drift/noisy rounds are present; these are costs to inform policy, not a performance acceptance gate.

Oracle: f64 evaluation of this crate's C0 curve, followed by nearest integer rounding. All 1,065,353,217 nonnegative f32 bit patterns in 0..=1, including subnormals, were enumerated. This is agreement with that f64 oracle, not a proof of real-number correct rounding.

Executable sizes are separate linked programs, not incremental library size; section layout and dead-code elimination differ. Both scalar and vector floor-corrected implementations were exhaustively checked. Its exact binary-scaled index uses the lower endpoint of a 4096-cell table plus one upward threshold comparison. Each cell spans less than one u8 code. Production adoption should freeze threshold bits rather than regenerate them through platform libm.

The fused measurement uses zenresize's actual incumbent unpremultiply/encode entry point. Candidate fused kernels use the same alpha threshold and scaling policy. Row length is pixels for fused RGBA, samples for encode. Times below are whole-call means; units are retained from zenbench.

## Recommendation

Keep the current default unchanged in this patch. Propose a separately reviewed accurate default using floor correction and an explicitly named approximate fast path. It costs 1024 extra table bytes. On these prototypes it adds observable time to long and fused rows; wider tables and the uncorrected polynomial still miss rounding boundaries. The scalar corrected variant is attractive for single samples, while floor correction fits vector kernels better. Full raw logs, executable hashes and inputs are retained outside git under `/mnt/v/output/linear-srgb/precision-2026-11-05/` and `~/tmp/precision-logs/` on r7900x.
